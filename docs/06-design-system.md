# 设计系统

状态：已实现。令牌在 `web/src/styles.css`，流程图形状在 `web/src/features/journey/`，终端配色在 `src/term.ts`。

读者是怀疑代码的工程师，页面要给人三种感觉：真实、安静、精确。下面的规则回答一个问题：这个元素凭什么出现、凭什么是这个样子。新增界面时先按这里选，选不出来再讨论，不要临时加样式。

## 颜色只表达一件事

每种颜色只有一个含义，所以读者可以相信它说的话。

| 颜色 | 含义 | 用在 |
| --- | --- | --- |
| 墨（ink） | 你在这里，以及一屏里唯一的主操作 | 当前节点、当前标签页、`stemap fix` 复制块 |
| 中性 | 其余一切 | 线、卡片、悬停、选中后的邻居 |
| 粉彩（sage、moss、sand、lilac） | 一条流程里被多步写入的表，最多四张 | 表的 chip |
| 深色搭档（teal、moss-ink、sand-ink、violet） | 同一张表画成线 | 追踪一张表时的线 |
| amber | 这句话依据的代码改了 | 漂移点、数量 |
| rose（`--destructive`） | 失败：失败路径，以及找不到依据的句子 | 失败节点、失败线、失败条件、抛错、未通过的句子 |
| cobalt（`--test`） | 判断：流程分叉的地方，以及决定分叉的条件 | 判断节点、线上的条件、面板的条件、判断逻辑的如果/拦下/否则 |

表的四个色相故意避开 rose、amber 和 cobalt：粉色的表会被读成失败，黄色的表会被读成代码改了。

- 新界面默认中性。只有确实属于上表某一行，才能用颜色。模块页的相关模块、悬停底色都不是表，所以都用中性。
- 同一屏只有一个实心节点。暗色下 chip 降到低明度，否则会盖过它。
- 墨在两个主题里是同一个东西：暗色的当前节点和当前标签页、主按钮一样是亮面深字，不另设灰块。
- 能装下别的盒子的盒子不填实心。它的子节点是独立元素，字色不会跟着反转，选中用 2px 描边。
- 变淡是为了让路，不是为了藏起来。追踪和模块选中时，正文对比度不低于 3:1，页面上要有一句话说明为什么变淡。
- 正常状态下所有文字对比度不低于 4.5:1，亮暗两个主题都要在真实页面上量过。
- 失败色高于当前路径的墨色：站在分叉上时，失败线仍然是失败线。

## 一个词只指一件事

| 词 | 指什么 |
| --- | --- |
| 判断 | 流程里分叉的节点，只指这个 |
| 一句说明 | 地图里写的一句话，对应代码里的 claim |
| 依据 | 这句话引用的代码。依据改了是 amber，找不到依据是 rose |
| 未确认 | 流程里的连线，代码索引没有找到它 |

## 字号只有五档

`display` 34、`title` 22、`body` 15、`ui` 13、`caption` 12。代码标题和总览卡片标题允许 17，这是仅有的例外。不写 `text-[13px]` 这类数字，也不用 `text-sm`、`text-xs`。`tailwind-merge` 已在 `web/src/lib/utils.ts` 登记这些角色，否则它们会被当成颜色合并掉。

## 节点靠形状说明自己

形状在放大缩小后都能认出来。判断是读流程时最要紧的节点，所以它不只靠形状。

| 节点 | 形状 | 含义 |
| --- | --- | --- |
| 判断 `decision` | 两端带尖的宽菱形，cobalt 粗边框和浅底，分叉图标加“判断 · 3 路” | 流程在这里分叉。形状、颜色、图标、文字四重信号，任何一种失效都还认得出 |
| 动作 `action` | 直角卡片 | 系统做一件事 |
| 子流程 `subflow` | 双边胶囊，左边折叠箭头，右边圆形打开按钮 | 里面是一条完整流程。点块选中这一步，和其他节点一样；点箭头就地展开，点按钮进入那条流程的页面 |
| 结束 `end` | 胶囊 | 流程走完 |
| 失败 `failure` | 玫红虚线胶囊 | 流程在此失败 |
| 开始 `start` | 带实心圆点的胶囊 | 流程从这里进入 |

同一个分叉图标（`TestMark`）出现在节点和步骤面板里，说的是同一件事。右侧进度条里，判断的刻度也是 cobalt，总览的流程指纹同样如此。

展开的子流程：胶囊留在原位，居中贴在一个浅底房间的顶边，线还是落在胶囊上，内部步骤排在房间里。选中状态只在胶囊上，房间不描边也不填实心。流程很宽时左上角会跑出屏幕，所以胶囊不放角上。进出房间的线和收起时一样，收起后图完全复原。站在房间里的步骤上时，面板顶部有收起入口，因为胶囊可能在很远的上方。每条流程按自己的长度决定是否折叠失败分支。

折叠的失败分支不会消失：节点下方留一小段玫红虚线和数量。它占一个真实端口，所以不会压在别的线上。

## 线

- 布局用 ELK 决定每条线穿过各层的位置，React Flow 负责渲染。`wirePath` 在层间画一条 S 曲线，线始终竖直进出，没有拐角。回流线在最高点横向穿过，避免尖角。
- 默认中性 1.25px。当前路径 1.75px 加墨色。颜色只在追踪表时出现。
- 虚线是失败或重试，点线是未确认。
- 终点用 React Flow 的闭合箭头，大小不随线宽变化。

## 条件写在线上

分叉的意义在条件，所以每个带条件的分支都把条件文字放在自己的线上。

- 位置由 ELK 预留，不会压到节点；横向居中到自己的线上，归属不会含糊。
- 标签是实底卡片加 cobalt 边框，文字用墨色，彩色文字压在浅色底上读不清；失败条件用玫红边框和玫红字。线从标签后面穿过，从当前节点出发的标签改成实色。
- 最多两行，全文在 tooltip 和步骤面板里。点击标签走这条分支。
- 步骤面板用同样的顺序：先写条件，再写去向，失败整行玫红。

判断逻辑是一张两列的表：左列动词，右列代码，代码从同一条竖线开始，只看动词就能读出函数的轮廓。这里不放图标，动词本身就是标记。

| 结构 | 动词 | 说明 |
| --- | --- | --- |
| 拦截 | 拦下，如果（cobalt） | `if (bad) throw` 或 `if (bad) return`，条件和结果收成一块，不用展开 |
| 如果 | 如果（cobalt） | 成立分支是墨色边线，否则分支是中性边线 |
| 分支 | 分支（cobalt） | `switch` |
| 遍历 | 遍历（墨色） | 循环 |
| 尝试 / 出错时 | 边线 | 出错分支用玫红边线 |
| 抛错 | 抛错（玫红） | 包括 `return throwApiError(...)` |
| 调用、返回 | 灰色 | 动作不是判断，让出视线 |

判断带 2px cobalt 竖线，和上方“接下来取决于”的分叉是同一条线。这一步引用的行铺 `--hit` 底。竖线和铺底都只画在最外层的盒子上，一块拦截不管引用了几行，都只有一层。

代码按人手换行的位置折行：括号外的空格和链式调用的点。`.where(eq(a, b))` 整段下移，放不下才在括号里断开。

## 键盘

每个可见操作都能用键盘完成，按键只有五组，`?` 随时列出全部：

| 按键 | 作用 |
| --- | --- |
| `←` `→` | 上一步、下一步 |
| `1`–`9` | 走面板里这个编号的分支，编号只在分支多于一条时显示 |
| `⌘K` `/` | 搜索 |
| `Esc` | 按打开的相反顺序收起：先源码，再详情，同时取消固定的追踪 |
| `?` | 这份说明 |

追踪一张表有两档：悬停是看一眼，点击是留下。留下时镜头移到这张表的整段范围，再走流程时追踪不消失。

## 漂移要能走完

总览的数字不是终点。一个文件展开后列出压在它上面的步骤和模块，点进去就是要重读的那一句；流程图例的琥珀计数是按钮，连按按流程顺序走完这条流程里每一处，右侧细轨同样标出它们。

## 取舍过的东西

- 没有动画流动、端口圆环、泳道底色、链接列表图标、搜索结果图标。删掉后什么都没少。
- 模块页不画关系线。线会穿过文字，相关模块保持全强度、其余淡出就够了，方向在面板的“关联”里。
- 浮层不做背景模糊，只用一层半透明遮罩。
- 句子和它的证据是一块，不拆到不同标签页。

## 终端

`stemap init`、`fix` 等线性流程用 Clack 的轨道样式，`stemap fill` 在交互终端用 Ink 面板，窄终端去掉日志列。`stemap status` 按文件分组，改动最多的在前。配色和页面同一套粉彩，`src/term.ts` 同时支持 truecolor 和 256 色。
